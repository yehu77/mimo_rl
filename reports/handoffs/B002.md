### B002.3：TaskBundle 隔离

`src/mimo_rl/task.py` 只使用标准库，提供 `SolverTask`、`RuntimeSpec`、
`VerifierSpec` 和 `TaskBundle`：

* solver payload 只允许 `task_id`、原始 `messages`、`problem_statement` 和
  `cwd`，不会透传完整 `extra_info`、未知字段、patch 或 command；
* `RuntimeSpec` 保存数据 revision、Parquet 0-based 行号、原始
  `extra_info.index`、mapping JSONL 行号和镜像映射；`repo_identity`、任务仓库
  `base_ref`、`image_digest` 没有来源时保持 `null`，状态为 `PENDING_RUNTIME`；
* `VerifierSpec` 私存 `test_patch`、`test_command`、timeout，默认 repr/摘要只
  输出长度和 SHA-256；`to_mimoagent_instance()` 才按官方八字段组成控制器对象。

解析过程不调用 `eval`、`exec`、`subprocess`，不解析或规范化宿主机路径，也不
导入上游运行依赖。

### B002.4：任务准备 CLI

`scripts/prepare_code_tasks.py` 先复用 `inspect_dataset(...,
strict_provenance=True)`，随后逐条执行 `TaskBundle.from_record()`。默认输出
`source_validation.json`、`task_catalog.jsonl` 和 `catalog_summary.json` 的脱敏
字段摘要；只有显式给出一个 `--task-id` 与 `--write-private` 才写入忽略目录
`private/` 的完整 controller bundle。输入失败也会进入 catalog，
`input_count == prepared_count + failed_count`。

### B002.5：不变量与隔离测试

`tests/unit/test_task_contract.py` 覆盖字符串/对象 instance JSON 等价、字段冲突、
无映射/重复 mapping 行号、序列化和输入不可变、solver 白名单、verifier 私有
hash、公共/私有输出隔离，以及禁止外部进程调用。R1 原有 native Parquet/CLI
回归保持在测试集中。`requirements-dev.lock` 固定本轮实际使用的核心数据和
测试依赖，未加入上游训练栈。
